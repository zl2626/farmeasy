后端代码位于 `backend/`（Django 5.2 + DRF，SQLite 数据库）。
**AI 助手已接入 DeepSeek（deepseek-v4-flash-vision-exp），配置好 key 即可测试。**

- ✅ 注册接口：支持中国 11 位手机号，重复项返回中文提示
- ✅ 登录接口：JWT + `/api/education/profile/`
- ✅ AI 助手：已从 Groq 切换为 **DeepSeek**（OpenAI 兼容接口）

  - 嵌入模型：`paraphrase-multilingual-MiniLM-L12-v2`（多语言，支持中英文检索）

## 日常启动

```bash
cd C:\Users\31586\Desktop\farmeasy\backend
venv\Scripts\activate
python manage.py runserver 127.0.0.1:8001
```

前端：`farmeasy-frontend` 目录 `npm run dev`。浏览器通过同源 `/api` 请求，Vite 自动代理至 `http://127.0.0.1:8001`，`npm run preview` 也支持该代理。

后端使用独立的 8001 端口，避免与其他项目的 8000 端口冲突。前后端都需要启动；本地开发不要把 `.env.example` 中的线上地址作为实际接口地址。如果后端改用其他端口，启动前端前设置 PowerShell 环境变量 `$env:API_PROXY_TARGET='http://127.0.0.1:端口'`。手机访问时前端使用 `npm run dev -- --host 0.0.0.0`，接口仍由 Vite 代理。

线上部署：Vercel 同源部署默认使用 `/api`；GitHub Pages 必须配置真实可访问的 HTTPS 后端地址 `VITE_API_BASE_URL`。后端需设置持久数据库 `DATABASE_URL`、`DJANGO_SECRET_KEY`、允许的域名与跨域来源，并完成数据库迁移。代码修复不会自动更新线上部署。

## 注册 bug 修复记录

原代码手机号校验为印度规则（10 位、6-9 开头），中国手机号注册必然失败，
且注册页不显示手机号错误信息。已修改 `farm_app/serializers.py`：

| 项目 | 修改前 | 修改后 |
|------|--------|--------|
| 手机号校验 | `^[6-9]\d{9}$`（印度 10 位） | `^1[3-9]\d{9}$`（中国 11 位） |
| 手机号重复 | 数据库直接报 500 | 返回"该手机号已被注册" |
| 用户名/邮箱重复 | 英文提示 | 中文提示 |
| 密码 | 无校验 | 至少 6 位 |
| 手机号字段长度 | 10 | 11（模型和迁移已同步修改） |
