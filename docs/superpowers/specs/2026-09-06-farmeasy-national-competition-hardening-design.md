# 智农平台国赛级工程加固设计

## 1. 目标

在不开展 AI 指标评测、真实农户试用、软著和答辩材料工作的前提下，将现有“智农”平台从演示原型升级为可复现、可部署、数据诚实、安全可靠、移动端可用的中国农业服务应用。

改造必须保留现有核心能力：用户注册登录、密码找回、作物知识、惠农政策、市场行情、农户提问、管理员回复、AI 文字问答、图片诊断、PDF 分析、多语言切换和后台管理。

## 2. 明确不做

- 不建设农业问答金标准集、病害图片测试集或算法消融实验。
- 不承诺或展示未经验证的准确率、召回率、幻觉率等 AI 指标。
- 不开展 20–30 名真实农户试用、软著申请或国赛答辩材料制作。
- 在没有中国官方行情 API 和合法凭据前，不实现或宣称实时行情。

## 3. 产品原则

1. **数据诚实**：离线数据必须标注“历史快照”或“演示数据”，展示来源和更新时间，不把生成数据包装为实时数据。
2. **沉浸与效率并存**：保留球形图库占据 `/home` 首屏的沉浸体验，同时提供不遮挡图片的轻量品牌与任务入口；装饰交互不得制造横向滚动、键盘陷阱或大量重复焦点。
3. **中国特色**：界面语言使用自然、准确、面向中国农户的简体中文；图片展示中国梯田、稻田、麦田、茶园、果园、温室、农技服务和乡村集市等真实农业场景。
4. **保留习惯**：保留现有 URL、主要导航名称和关键工作流；视觉优化不得增加完成任务的步骤。
5. **可降级**：AI、联网搜索或未来行情提供方不可用时，系统返回明确状态和可继续使用的本地功能，不显示调试页或伪造结果。

## 4. 总体架构

### 4.1 前端

- React/Vite 继续作为前端技术栈。
- 建立统一 API 客户端，API 根地址由 `VITE_API_BASE_URL` 配置，统一处理认证、超时、错误消息和 401 刷新。
- 路由按页面懒加载，降低首包体积。
- 删除市场、作物和政策页面的隐式静态回退；所有业务数据来自后端标准接口。
- 页面必须分别呈现加载、空数据、离线、失败和正常状态。
- 保留当前路由；未登录访问受保护页面时跳转登录页，并携带原目标地址。

### 4.2 后端

- Django REST Framework 继续作为 API 层。
- 按开发和生产环境读取配置；密钥、邮件配置、允许域名、CORS、前端地址和外部 API 凭据全部来自环境变量。
- SQLite 用于本地演示；配置结构允许部署时切换 PostgreSQL，但本次不强制引入额外数据库服务。
- 新增幂等数据导入命令，将现有中国作物和政策资料写入数据库。
- 新增行情提供方边界：当前只提供带来源与快照日期的离线中国行情；将来通过同一接口接入官方 API。
- API 返回稳定的 JSON 错误格式，不向客户端暴露堆栈、文件路径、密钥或外部服务原始异常。

### 4.3 AI 上下文

- AI 助手保留文字、图片和 PDF 能力。
- 用户可选填地区、作物、生育阶段，作为结构化上下文传入问答。
- 回答展示本地知识来源、资料类别和更新时间；联网补充内容明确区分。
- “高/中/低置信度”不得由单一关键词直接判定。若没有可靠校准，界面改为“本地资料命中”“含网络补充”“资料不足”等可解释状态。
- 医药、农药剂量、食品安全等高风险建议必须提示以产品标签和当地农技部门意见为准。

## 5. 安全设计

- 立即移除并轮换代码中已经暴露的 Django 密钥和邮箱应用密码。
- 密码找回统一返回不泄露账号存在性的响应；重置时必须验证 UID、token 和 Django 密码规则。
- JWT 访问令牌仅短期保存；刷新失败时清除认证状态并跳转登录。生产环境要求 HTTPS 和安全 Cookie 配置。
- CORS 使用明确的前端来源列表，禁止全域开放。
- 图片和 PDF 上传同时验证扩展名、MIME、文件签名和解析结果，并限制大小、页数、像素与处理超时。
- 对登录、注册、密码找回、AI、抓取和反馈接口实施速率限制。
- 外部网页仅允许经过配置的农业或政府域名；抓取文本作为不可信资料处理，不允许其覆盖系统指令。
- 管理接口继续执行服务端 `is_staff` 校验，前端隐藏不能替代后端授权。

## 6. 数据设计

### 6.1 作物与政策

- 为所有现有模型补齐迁移并统一主键策略。
- 作物数据保存名称、类别、季节、土壤、气候、需水、肥料、种植步骤、常见错误、来源、来源日期和图片。
- 政策数据保存名称、适用地区、政策类别、发布机构、发布日期、有效状态、资格条件、办理方式、官方链接和来源更新时间。
- 导入命令可重复执行，不产生重复记录。

### 6.2 行情

- 当前前端生成的随机价格不再作为业务数据。
- 离线快照通过后端接口返回 `source_name`、`source_url`、`snapshot_date`、`data_mode=historical_snapshot`。
- 页面标题使用“农产品行情参考”，并明确声明数据仅供演示或历史参考。
- 将来官方 API 提供方只需实现统一 provider 接口，不改变前端字段和筛选行为。

## 7. 界面与视觉设计

### 7.1 首页

- 保留现有 `/` 启动页和 `/home` 路由，不改变用户当前进入路径。
- 球形图库继续完整占据 `/home` 第一视口，并作为中国农业视觉主场景。
- 图库照片全部替换或核验为真实中国农业生产场景，保证作物、田块或农户活动清晰可辨。
- 在不遮挡图库主体的前提下，提供“智农”品牌、简短价值说明和文字咨询、拍照诊断、查作物、看行情快捷入口；入口可放在透明度受控的轻量覆盖层或首屏下沿。
- 图库的视觉复制元素从无障碍树中隐藏，只保留一组可操作项；手机端不得出现水平滚动。

### 7.2 业务页面

- 采用克制的绿色、白色、炭灰色和少量金黄色，避免整页单一绿色。
- 使用统一的 Lucide 图标；Emoji 只作为正文语气元素，不作为结构性图标。
- 作物卡片只显示经过作物名称核对的真实照片，并提供类别、适种季节和主要地区等可扫描信息。
- 每张作物照片维护作物名称、来源地址、作者/机构、许可和核验状态。无法确认物种或许可时使用统一中性占位，不使用 Emoji、相似作物或 AI 合成图冒充真实照片。
- 行情采用表格/列表与趋势信息组合，优先支持地区和品类比较，不用大批重复卡片堆砌。
- 政策突出适用地区、发布时间、发布机构、办理状态和官方入口。
- AI 助手保持对话效率，补充结构化上下文选择器、来源区域、失败重试和安全提醒。

### 7.3 响应式与无障碍

- 验证 375×812、768×1024、1440×900 三类视口，无水平滚动和内容遮挡。
- 所有交互元素具备键盘可达性、清晰焦点、可访问名称和至少 44px 的有效点击区域。
- 表单必须有真实 `label`、字段级错误和提交错误摘要。
- 弹窗实现焦点圈定、Escape 关闭、关闭后焦点恢复。
- 装饰图片使用空替代文本，信息图片提供准确中文替代文本。
- 支持 `prefers-reduced-motion`，关闭非必要动画。

## 8. 工程质量

- 实施前在当前目录初始化本地 Git 仓库，排除虚拟环境、密钥、数据库、用户上传和构建产物后，创建“改造前基线”提交；不配置远端、不上传任何文件。
- 清理源码目录中的虚拟环境、缓存、构建产物、用户上传文件和本地数据库跟踪规则；不删除用户本机数据，只通过 `.gitignore` 和文档规范隔离。
- 提供项目级 README、`.env.example`、依赖安装、数据导入、运行、测试和部署说明。
- 提供 Dockerfile 和 Compose，一条命令可启动前后端；生产服务使用正式 WSGI 服务而不是 Django 开发服务器。
- 前端依赖升级到无已知高危漏洞的兼容版本。
- 修复全部 ESLint 错误，消除 Django 迁移漂移和部署检查中的项目级安全警告。

## 9. 测试与验收

### 9.1 后端测试

- 密码重置：无效 token、过期 token、弱密码、未知邮箱和有效重置。
- 权限：匿名、普通用户和管理员分别覆盖关键接口。
- 数据：迁移、幂等导入、空数据库、行情快照元数据。
- 上传：伪造扩展名、错误 MIME、超限文件、损坏文件和正常文件。
- AI：外部服务失败、向量库不可用、资料不足和会话隔离。

### 9.2 前端测试

- API 客户端、认证刷新、受保护路由和错误状态。
- 首页快捷入口、行情筛选、作物搜索、政策详情和 AI 上下文输入。
- 无数据、后端失败和超时状态不得静默使用伪造数据。

### 9.3 完成标准

- `npm run build`、`npm run lint` 和前端测试全部通过。
- Django 测试全部通过，`makemigrations --check --dry-run` 无变化。
- 生产配置下 `manage.py check --deploy` 不再报告由项目配置造成的关键安全警告。
- 依赖审计无高危漏洞。
- 关键接口不返回 HTML 调试页。
- 三类目标视口通过浏览器截图和溢出检查。
- 所有原有核心功能仍有可达入口和正常/失败状态。

## 10. 实施顺序

1. 建立测试基线和安全配置。
2. 修复密码、迁移、上传、权限和异常处理。
3. 建立数据库导入与行情 provider，移除伪造数据回退。
4. 统一前端 API 与认证，完成路由懒加载。
5. 重构首页、导航、行情、作物、政策和 AI 助手界面。
6. 建立图片来源清单，引入并逐张核验中国特色农业与农作物真实照片。
7. 完成响应式、无障碍、依赖与部署文档。
8. 执行完整回归、浏览器视觉检查和安全检查。
